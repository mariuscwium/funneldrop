# Game-over Conditions Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add three ways to lose: Ran out of runway, Ousted by the board, and Shut down. Each one is preceded by warnings and a visible countdown, and the hidden alignment shapes their odds and severity.

**Architecture:** Everything lives in `Funnel Drop.html`'s single script, as in the rest of the game. Game-over state is advanced once a game month, in the rollover branch of `loop`, by one `rollRisk()` call. That call runs insolvency, the soft-lock, the board and case rulings in that order. Endings go through one `endGame(kind)`, which snapshots a summary into the new `#over` dialog. The board and cases add small amounts of saved state, using the existing defaults-on-load pattern.

**Tech Stack:** Vanilla JS/HTML/CSS in one file, and `node --test` on Node 22 with `tests/harness.js`. No packages.

**Spec:** `docs/superpowers/specs/2026-11-08-game-over-design.md`

## Global Constraints

- No UI, event, warning, ruling or end-screen text may match `/\b(good|evil|lawful|chaotic|alignment|ethic\w*)\b|dark pattern/i`. The tests extend `tests/alignment.test.js` to check this.
- Nothing in this plan runs while `ipoFiled` or `over` is set. Use `atRisk()` (Task 1) as the single guard.
- No ending may fire without a warning for the same cause recorded earlier in `over.story`.
- Endings pause the game. While `over` is set, every spending handler returns early, like `ipoFiled`. Firing staff and paying off loans still work.
- New saved state uses defaults on load (missing → 0, false or null). **Don't bump `SAVE`.** The spec says to bump it, but every earlier shape change has used defaults on load, and bumping the key would wipe players' runs. This is my call and overrides the spec line.
- All new numbers are named constants near their feature, with the spec's starting values: `INSOLVENT_MONTHS` 3, `SOFTLOCK_MONTHS` 2, `BRIDGE_MONTHS` 3, `BRIDGE_MIN` 5000, `BRIDGE_APR` .45, `BOARD_START` 70, `BOARD_REST` 60, `BOARD_WARN` 40, `BOARD_ULT` 20, `ULT_MONTHS` 6, `ULT_LAWFUL` 9, `ULT_SHORT` 4, `ULT_REPEAT` 24, `CASE_AT` -.4, `CASE_SHUT` -.7, `CASE_MONTHS` 12.
- Text uses the game's voice: plain business terms, sentence case and curly apostrophes (’), as in `EVENTS`.
- Commits go on branch `puffin` only. Never push.
- Run the suite with `node --test 'tests/*.test.js'`. All 181 existing tests must stay green.

## Review Focus

1. **A dialog already open at rollover.** An event, the milestone dialog or the roadmap may be open when `rollRisk` wants a warning. `loop` doesn't run while a dialog is open, so the rollover can't happen inside one. But a single rollover can raise an event *and* a warning. The warning must queue, not overwrite `#ev`. Test in Task 1: a rollover that produces both shows both, one after the other.
2. **Reloading mid-countdown.** Insolvency count, ultimatum deadline and open case must survive save and load and carry on from where they were. Each owning task has a round-trip test.
3. **Respec mid-case.** Respec changes exposure. The ruling reads `companyAl()` at ruling time, so a respec before the ruling must change the band. Test in Task 5.
4. **Cash negative at filing time.** `ipoFiled` must freeze every countdown at once, and a filed game must never end. Test in Task 1 (`atRisk`), with one check per later task.
5. **The board created on an old save already past $1M.** `load` creates it at `BOARD_START` with no ultimatum and no instant warning. Test in Task 4.

- Test: `tests/board.test.js` (new)

**Interfaces:**
- Consumes: `warn`, `endGame`, `atRisk` (Task 1), `netFlow`, `runway`, `insolventNow` (Task 2), `stale`, `STALE_GRACE`, `yoy()`, `growth`, `companyAl()`.
- Produces:
  - `let board=null`, shaped `{conf, last, why, pend, shipped, ult, lastUlt, warned}`:
    - `conf`: the number
    - `last`: the last change
    - `why`: `[[label, delta]]` from the last rollover
    - `pend`: `[[label, delta]]` queued since then
    - `shipped`: a bool for this month
    - `ult`: the deadline month, or null
    - `lastUlt`: the month the last ultimatum ended, or null
    - `warned`: a bool
  - `boardHit(label, n)`: if `board`, push `[label, n*(n<0&&companyAl()[1]<=-.3?1.5:1)]` to `pend`.
  - `boardReasons(): [[string, number]]`. A pure function of state. It doesn't include `pend` or the ship bonus.

    | Reason | Change |
    |---|---|
    | Nothing shipped | `-min(5, max(0, stale-STALE_GRACE))`, only while `staleOn` |
    | Growing | +2 at `yoy()>.4` |
    | Shrinking | −3 at `yoy()<0` |
    | Runway | −2 at `runway()!=null && runway()<6` |
    | Can’t pay bills | −5 at `insolventNow()` |

    Before 13 ledger months, `yoy()` is null; use 3-month `growth` with the same signs, at `growth*12>.4` and `growth<0`. Zero-delta reasons are dropped.
  - `boardMonth()`: run first in `rollRisk`'s board step.
    - `why = boardReasons() + pend + (shipped ? [['Shipped',2]] : [])`.
    - If `why` is empty, drift 1 toward `BOARD_REST` and record `[['Steady',±1]]`.
    - `conf = clamp(conf + Σ, 0, 100)`. Then clear `pend` and `shipped`.
  - `ultMonths(): number`:
    - `ULT_SHORT` if `lastUlt!=null && month-lastUlt<ULT_REPEAT`
    - otherwise `ULT_LAWFUL` if `companyAl()[1]>=.3`
    - otherwise `ULT_SHORT` if `companyAl()[1]<=-.3`
    - otherwise `ULT_MONTHS`

**Rules after `boardMonth()`:**
- `conf<BOARD_WARN && !warned`: `warn('board','The board is concerned', …)`, listing the two most negative reasons with one fix each. When lawful (`companyAl()[1]>=.3`), add "Your track record buys you some patience." Set `warned`.
- `conf>=50`: `warned=false`.
- `conf<BOARD_ULT && ult==null`: `ult=month+ultMonths()`, then `warn('board','Ultimatum from the board', …)`, which says "above 40 within N months".
- `ult!=null && conf>BOARD_WARN`: `lastUlt=month; ult=null`, plus a `say` that the board backed off.
- `ult!=null && month>=ult`: `endGame('board', ENDINGS.board, …)`.

**Other hooks:**
- `buyNode` success sets `board.shipped=true`.
- The milestone dialog calls `boardHit('Milestone',10)` for milestones after the board exists.
- Regulator fine, Class action, Data breach and Viral complaint each call `boardHit(name,-6)`.
- `load`: `board ??= peak>=1e6 ? fresh board : null`. A fresh board is `{conf:BOARD_START, last:0, why:[], pend:[], shipped:false, ult:null, lastUlt:null, warned:false}`.
