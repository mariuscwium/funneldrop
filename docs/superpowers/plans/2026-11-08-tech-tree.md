# Tech Tree Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace Funnel Drop's Upgrades list with a constellation tech tree in a full-screen modal: nodes are paid for with roadmap points and cash, forks are mutually exclusive, and a hidden alignment steers random events.

**Architecture:** Upgrade effects move from the fixed `TRACKS` tiers to a cached effect sum (`FX`) over owned nodes. Slot widths come from per-board width↔rate tables measured with the sims, so a node can add any number of rate points. Roadmap points are a new resource earned monthly from the founder, a new Engineer role and milestones, capped at a quarter's output. The modal is a `<dialog>` with an SVG constellation that pauses `loop` like `#ev`.

**Tech Stack:** One file, `Funnel Drop.html` (inline CSS and JS, canvas, SVG). Node 22 `node:test` through `tests/harness.js`. Sims in `sim/`.

**Spec:** `docs/superpowers/specs/2026-11-08-tech-tree-design.md`

## Global Constraints

- Everything stays in `Funnel Drop.html`. No build step, no dependencies beyond Google Fonts.
- Tests run with `node --test 'tests/*.test.js'` and must all pass at the end of every task.
- `zone(b)` stays the only place that sets a board's slot width. Physics (`physics`, `PEG_ROWS`, gravity, pegs, ball size) must not change; the ball-path fingerprint test in `tests/perf.test.js` must keep passing.
- Every spending action, including node purchases and the respec, returns early and is disabled while `ipoFiled`.
- New game state goes into `save` and `load`. Old saves (with `lvl`, without `owned`) must load and convert. Keep the `SAVE` key `funnel-drop-save-v1`, since the change is additive and `load` can detect old saves.
- **Alignment is hidden.** No node name, description, colour, badge, tooltip, event text or UI string may mention alignment, ethics, "good", "evil", "lawful", "chaotic" or "dark pattern". Node text says what the node does, in product terms, with numbers.
- Colours are CSS tokens that work in both themes. Canvas colours come from `C` via `readColors`. Text on `--ad` uses `--on-ad`.
- The modal must work at 360px wide on touch (drag to pan, pinch to zoom) and with mouse (drag, wheel zoom).
- Numbers repeated in copy (`#msg`, `.src`) match the constants. Invented effects are labelled game simplifications in `.src`.
- Every task updates the matching parts of `CLAUDE.md` (Code map, Gotchas) and `README.md` for what it changes.

## Review Focus

1. **Closing the tree resumes cleanly.** Queued visitors, the post cooldown and payroll cuts shift by the time the tree was open, like `#ev`. Pinned in Task 6.
2. **Buying with only one resource is a no-op.** Enough points but not enough cash, or the reverse, changes nothing. So do an unreachable node, a node on the losing side of a fork, and anything while `ipoFiled`. Pinned in Task 2.
3. **An old save converts exactly once.** Loading a converted save again must not refund points or re-add nodes. A maxed old save (all tiers 3) loads with its seeds owned and refunded points. Pinned in Task 4.
4. **The tree stays readable at phone width.** No two node centres are closer than twice the node radius, and every node lies inside the layout bounds. Pinned in Task 7.
5. **Stacked rate bonuses can't break physics.** With every rate node on a board owned, plus 3 role hires and the best price, the width stays at or under the board's table maximum and under 340px. Pinned in Task 1.

### Task 2: Nodes, forks, effects and buying

The headless core of the tree. It ships with only the seed nodes plus a few test nodes; Task 7 writes the full content.

**Interfaces:**
- Consumes: `RATES`, `bonus`, `CHURN0` from Task 1.
- Produces:
  - **Node definition**, in `NODES`: `{id, name, desc, area, ring, slot, links:[ids], fork:null|string, pts, cash, al:[g,l], fx:{key:value}, rep:false}`.
    - `area`: 0–5 is a funnel wedge; `[a,b]` is a keystone between wedges a and b.
    - `ring`: 1 or more, the distance out from the centre.
    - `slot`: −1..1, the angular offset inside the wedge.
    - `cash`: base cash at $0 valuation.
    - `al`: hidden, each value in [−1, 1].
    - The start node is `{id:'start', ring:0}`, always owned and free.
  - **Effect keys in `fx`.** All effects are deltas that sum across owned nodes and repeats.
    - `r0`..`r5`: rate points on board b (feeds `bonus`).
    - `churn`: relative change to `CHURN0` (−.1 means 10% lower).
    - `priceTol`: shrinks how far `priceConv` and `priceChurn` move away from 1. Clamp at .8.
    - `adCost`, `adReach`: relative change to `adCost`/`campCost` and to `perAd`.
    - `refSize`: relative change to friends per referral.
    - `custRef`: relative change to `CUST_REFER`.
    - `down`: relative change to `DOWN_RATE`.
    - `cts`: relative change to `COST_TO_SERVE`.
    - `csm`: relative change to `CSM.covers`.
    - `seo`: relative change to search traffic.
    - `rp`: relative change to roadmap point income.
    - `evGood`: shift in the good-news chance, in points.
  - `owned`: an object, `id → count`. `FX`: the cached sums. `refx()` rebuilds `FX`, then sets `bonus`, `churn` and all zones. It is called on buy, respec and load. **Hot paths read `FX`, never `owned`.**
  - `nodeState(id)`: one of `'owned'|'available'|'locked'|'unreachable'|'closed'`. `closed` means Expansion before `expOpen()`. `locked` means the losing side of a fork.
  - `nodeCash(n)` = `n.cash * mkt()**AD_PRICE_P`. `nodePts(n)` = `n.pts + (n.rep ? owned[n.id]||0 : 0)`.
  - `buyNode(id)`: returns true when bought. It requires `available`, `rp >= nodePts`, `cash >= nodeCash` and `!ipoFiled`. It spends both through `spendCash` (cash) and `rp` (points), increments `owned`, calls `refx`, `markShipped()` (Task 3; a stub now) and `say` with the node name and its effect.
  - `rp` (number): roadmap points. Task 3 adds income. Start with `RP_START = 2`.
- Seed nodes: one in ring 1 of each wedge, with no fork, holding today's tier-1 upgrade as its effect. Ids: `acq1` "Market research" `{r0:.032}`; `act1` "Onboarding checklist" `{r1:.095}`; `ret1` "Lifecycle emails" `{r2:.055}`; `ref1` "Share button" `{r3:.10}`; `rev1` "Pricing page" `{r4:.10}`; `churn1` "Cancellation save offers" `{churn:-.2167}` (in the Retention wedge); `exp1` "Usage-based pricing" `{r5:.04}`. Each costs 1 point and $2,000 cash, except `exp1` at $50,000, matching today's prices.

  - **Evil-adjacent bad events don't fire without exposure.** Every new bad event has `when` requiring `companyAl()` on its axis to be ≤ −.15 (or ≥ .15 for the lawful-axis ones). The spec wants consequences driven by alignment, not random punishment.
